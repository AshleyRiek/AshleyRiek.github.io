Professional Self-Assessment

This self-assessment summarizes my growth throughout the Computer Science program and explains how the artifacts in this ePortfolio demonstrate the CS 499 program outcomes through deliberate enhancements, technical refinement, and professional presentation.

1) Strengths, Goals, and Professional Preparation

Throughout the Computer Science program, my approach to development evolved from focusing primarily on functional correctness to building solutions that are maintainable, measurable, secure, and professionally structured. The capstone experience required not only implementing enhancements, but also analyzing original designs, identifying structural weaknesses, justifying improvement strategies, and clearly communicating those decisions. This shift from task completion to intentional engineering reflects my development into a more mature computer science practitioner.

My strengths include structured problem-solving, clear documentation, and thoughtful trade-off evaluation. I approach technical challenges by identifying requirements, analyzing design alternatives, considering performance and scalability implications, and integrating security considerations early in the process. Professionally, I aim to continue developing as a well-rounded computer science professional who contributes both through technical execution and through planning, communication, and system-level thinking.

2) Collaboration and Communication

Effective software development requires clear communication and collaboration. Across the program, I strengthened my ability to explain system behavior, justify technical decisions, and document improvements in a format suitable for stakeholders and future developers. The informal code review included in this portfolio reflects that growth by presenting existing functionality, identifying structural and security concerns, and outlining an enhancement plan aligned with program outcomes. The enhancement narratives further demonstrate my ability to translate technical improvements into professional documentation that communicates purpose, impact, and results.

3) Data Structures, Algorithms, Software Engineering, Databases, and Security

In Software Design and Engineering (CS 360), I enhanced an inventory management application by restructuring the architecture to improve maintainability and clarity. I introduced a dedicated service layer (InventoryService) to separate business logic from the user interface and implemented a validation framework (InventoryValidator and ValidationResult) to enforce consistent input handling. Guard clauses were added to prevent null or malformed input from causing instability. I implemented duplicate-prevention using SKU-based uniqueness with a name-based fallback, added input normalization for consistent formatting, and introduced audit logging with an admin-only audit screen to promote accountability and traceability. Additionally, I implemented a repository abstraction layer and centralized message registry to support cleaner architecture and improved scalability. These enhancements demonstrate applied software engineering principles, modular design, maintainability, and a security-aware development mindset.

In Algorithms and Data Structures (CS 300), I enhanced a C++ sorting and bid management application originally implementing Selection Sort and QuickSort. I introduced detailed performance instrumentation to measure execution time, comparison counts, and swap/move operations, enabling objective algorithm evaluation. I improved the QuickSort implementation using a median-of-three pivot strategy to reduce worst-case behavior on partially sorted datasets. I also implemented Merge Sort to provide a stable O(n log n) alternative and added a structured comparison framework to run algorithms on identical dataset copies for fair analysis. These enhancements transformed the artifact into a structured evaluation tool that demonstrates algorithmic reasoning, empirical trade-off analysis, and evidence-based decision making.

In Databases (CS 340), I enhanced a MongoDB-based CRUD application to improve portability, integrity, and performance. I added support for environment-variable-based MongoDB URI configuration with a localhost fallback to increase deployment flexibility. I implemented lightweight input validation and string cleaning for create and update operations to promote data consistency. To address scalability, I introduced both single-field and compound index creation for common dashboard filters (such as breed, sex_upon_outcome, and age_upon_outcome_in_weeks), improving query performance as the dataset grows. These enhancements reflect thoughtful trade-off analysis between indexing overhead and read performance while emphasizing responsible data handling and reliability.

Across all three artifacts, I consistently applied a security mindset by strengthening validation, reducing assumptions about input correctness, improving structural separation of concerns, and documenting decisions clearly. Rather than optimizing for performance alone, I considered maintainability, clarity, scalability, and risk mitigation when implementing improvements.

4) How the Artifacts Fit Together

The artifacts in this ePortfolio collectively demonstrate the five CS 499 outcomes. The CS 360 artifact reflects applied software engineering practices, modular architecture, and security-aware design. The CS 300 artifact demonstrates algorithmic analysis, performance measurement, and structured trade-off evaluation. The CS 340 artifact highlights database integration, data integrity, and scalability planning through indexing and configuration improvements. Supporting these artifacts, the informal code review documents existing functionality, identifies structural and security concerns, and maps enhancement strategies to program outcomes. Together, these components demonstrate my ability to design and evaluate computing solutions, communicate technical decisions professionally, use well-founded tools and techniques, and implement secure and maintainable systems that deliver value.
